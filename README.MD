# Classroom-ESP32

ESP32-S3 教室环境监测器：SSD1306 OLED 实时显示两路光照、MQ135 和 DHT11 数据，使用 EC11 调整四项告警阈值。

## 接线

| 模块 | 模块引脚 | ESP32-S3 GPIO |
| --- | --- | --- |
| SSD1306 OLED | SDA | 17 |
| SSD1306 OLED | SCL | 18 |
| EC11 | CLK | 4 |
| EC11 | DT | 5 |
| EC11 | SW | 8 |
| 低电平触发无源蜂鸣器模块 | SIG | 9 |
| 光敏模块 1 | AO | 7 |
| 光敏模块 2 | AO | 6 |
| MQ135 模块 | VCC | 5V |
| MQ135 模块 | AO | 经 10kΩ/18kΩ 分压后接 15 |
| DHT11 | DATA | 16 |
| LD2402 人体存在雷达 | OUT | 10 |
| DS3231SN RTC | SDA | 47 |
| DS3231SN RTC | SCL | 48 |
| 舵机信号 | PWM | 21 |
| L9110H 风扇 | IN1 / IN2 | 41 / 42 |

所有模块必须共地。EC11 按键按下为高电平，程序使用 GPIO 8 的内部下拉。无源蜂鸣器模块由 GPIO9 输出 2.4kHz 方波，停止时保持高电平以兼容低电平触发。裸蜂鸣器或 5V 大电流蜂鸣器必须通过三极管/MOSFET 驱动，不能直接由 GPIO9 供电。

DS3231SN 使用独立的两线 I2C 总线（GPIO47/48），OLED 使用另一组 I2C 总线（GPIO17/18），两者不共线。启用 8MB OPI PSRAM 时不要使用 GPIO35/36/37，这些引脚属于 PSRAM 总线。DS3231 的 SDA/SCL 需要上拉到 3.3V（多数模块已自带），地址通常为 `0x68`。RTC 上电后作为所有实际日期时间的唯一来源；联网成功后按配置的 NTP 服务器校时并回写 RTC。系统时区固定为 `Asia/Shanghai`（UTC+8），主页下方的“时间与 NTP”区域（也可直接访问 `/time`）会显示上海时间，并可修改 NTP 服务器或手动校时。

舵机信号接 GPIO21，舵机电源应使用独立 5V 供电并与 ESP32 共地，不能从 ESP32 3.3V 直接给舵机供电。温度、湿度、AQI 三项中至少两项超过各自阈值时，舵机转到 180°位置；恢复到少于两项超限时回到 0°。若机械安装方向相反，交换舵机的 500us/2500us 端点定义即可。L9110H 的 IN1/IN2 接 GPIO41/42，风扇电机使用独立电源并与 ESP32 共地；温度、湿度、AQI 任意一项超阈值时自动启动。

主页时间卡片下方的“调试执行器页面”（`/actuators`）提供舵机半圆拖动环（0°-180°）和 L9110H 风扇的速度、方向、停止及自动控制调试。

若串口提示 `no I2C ACK at 0x68`，请检查模块供电为 3.3V、共地、SDA/SCL 是否接反、GPIO47/48 是否与板卡实际引脚一致，以及模块是否存在 4.7kΩ 左右的 SDA/SCL 上拉电阻。

> 注意：MQ135 加热器使用 5V 供电，但 ESP32-S3 GPIO 只能接受 **0–3.3V**。请按 `MQ135 AO → 10kΩ → GPIO15 → 18kΩ → GND` 接入分压，理论上可把 5V 最大输入降至约 3.21V；所有模块必须共地。不要把 5V 供电模块的 AO 直接接 GPIO15。

> LD2402 的 OUT 按高电平“有人”、低电平“无人”读取并接 GPIO10。必须确认 OUT 高电平不超过 3.3V；若模块输出 5V，请先分压或做电平转换。模块电源按你所用板卡的规格连接。

## 使用方式

- 上电后，OLED 第一行并排显示两路光照，后面三行显示估算 AQI、温度和湿度。
- WebUI 和串口显示 LD2402 人体存在状态；GPIO10 高电平表示“有人”，低电平表示“无人”。OLED 不显示人体状态，该状态也不参与环境阈值蜂鸣器报警。
- MQ135 冷启动后先预热 3 分钟，并在最后 60 秒建立本次开机基线；基线约对应 AQI 50，随后按 AO 相对基线的变化映射为 `0–500` 估算 AQI。
- MQ135 不能通过一条 ADC 线性公式直接换算 ppm。真实 ppm 必须确定模块负载电阻、标定每只传感器的 R0，并使用目标气体对应的灵敏度曲线；本项目在未完成这些标定前不再显示伪 ppm。
- 这里的 AQI 用于观察同一台设备的空气变化趋势和触发告警，不是依据 PM2.5、PM10、臭氧等污染物浓度计算的国家标准 AQI。建立基线期间应尽量保持空气洁净稳定。
- 串口波特率为 `115200`。传感器和 EC11 不输出采样/按键日志；RTC 只在启动时输出检测结果，运行期间不输出 I2C 逐字节调试信息。舵机和风扇每 2 秒输出一次执行状态。
- EC11 只参与本地交互，不输出串口调试信息。
- 在主界面按住 EC11 达到 500 ms 会立即进入设置，无需松手；旋转选择项目，短按进入调节；再次短按确认，长按返回主界面。
- 在设置页移动到“湿度”再向下旋转，可打开只读网络信息页，查看设备 IP、最近数据上报、最近心跳上报和 API 连通状态；Wi-Fi 未连接时 IP 显示“未连接”，向上旋转即可返回阈值列表。
- 光照阈值是下限，两路光敏中任意一路低于它都会告警；AQI、温度和湿度阈值是上限。任一项目从正常跨越到告警时，GPIO9 向低电平触发无源蜂鸣器输出 2.4kHz 方波约 0.5 秒且只响一次；数值持续超限不会循环鸣叫，恢复正常后再次越界才会重新报警。阈值在短按确认时保存到 ESP32 本地 NVS，告警数据在 OLED 行末显示实心圆。

阈值调节步长：光照和湿度为 1%，AQI 为 5，温度为 0.5°C。升级到 AQI 单位后，旧版空气阈值会自动作废并恢复为 AQI 100。

## 首次 Wi-Fi 配网与 WebUI

首次上电（或保存的 Wi-Fi 连接失败时）设备会创建无密码热点 `RX-Classroom-demo`：

- OLED 会显示热点 SSID、`无密码` 提示和配网页入口二维码。
- 手机先连接该热点，再扫描二维码；未自动打开时访问 `http://192.168.4.1/`。
- 在 WebUI 点击“扫描附近 Wi-Fi”后，SSID 输入框可选择扫描结果；隐藏网络也可以手动输入名称。
- 在 WebUI 填写路由器的 SSID 和密码并提交。设备会关闭配网热点、连接路由器；连接失败 15 秒后会自动重新开启配网热点。
- OLED 的配网提示显示 1 分钟后自动回到监测页，但热点和 WebUI 会一直保留。EC11 不再提供关闭热点的操作，避免按键抖动或误触导致热点消失。
- 已成功配网后，在同一局域网使用串口日志中显示的 IP 地址访问 WebUI，可查看光照、空气、温湿度的实时数据，也可清除 Wi-Fi 并重新配网。

Wi-Fi 名称和密码存入 ESP32 本地 NVS，不会上传到任何服务器；阈值使用独立的 NVS 命名空间，不会被清除 Wi-Fi 操作影响。设备只在开机时自动尝试一次已保存的 Wi-Fi，运行中断线不会反复重连；连接失败才进入配网。

## 数据上报

WebUI 的“数据上报”区域可配置 API Base URL（例如 `https://api.example.com/api`）和可选的设备 Token。配置保存到独立的 NVS 命名空间；浏览器只能查询 Token 是否已配置，不能读回 Token 明文。再次保存时 Token 留空会保留原值；未配置 Token 时请求不包含 `Authorization`。数据上报间隔可调为 1 秒至 86400 秒，默认 10 秒；心跳间隔可调为 0（关闭）至 86400 秒，默认 60 秒。页面轮询只更新设备状态，不会覆盖已经加载或正在编辑的表单。

- 设备 ID 自动取芯片 MAC，格式为 `esp32s3-XXXXXXXXXXXX`，可在 WebUI 查看。
- 连接路由器后立即向 `<Base URL>/reports` 上报一次 JSON，此后按 WebUI 配置的间隔发送；“立即上报当前数据”按钮可手动触发一次。
- 心跳与常规上报独立计时，并向同一个 `/reports` 地址携带完整的当前传感器数据；两种周期同时到期时只发送一条 `heartbeat` 请求并同时满足本次数据上报，不会重复请求，也不会再发送仅含 `device_id` 的空数据。
- 请求固定使用 `POST`、`Content-Type: application/json; charset=utf-8` 和 `Connection: close`；配置 Token 后增加 `Authorization: Bearer <设备Token>`。
- API Base URL 决定实际连接的协议、主机和端口。支持 `http://` 和 `https://`，HTTPS 默认使用端口 443，并通过固件内置的受信任根 CA 包校验证书链和域名，不会降级为不安全连接。
- HTTPS 上报前会在后台通过 SNTP 同步证书校验时间，同步期间 WebUI 和传感器继续运行，请求会暂缓而不会绕过校验；20 秒仍未取得时间时回调日志记录错误 `-13`，之后继续自动重试。
- 固定上报两路光照百分比、两路 ADC 原始值和 LD2402 的 `presence`；MQ135 预热完成后才包含 `aqi`，DHT11 读数有效时才包含 `temperature` 和相对湿度 `humidity`（单位 `%`，范围 0–100）。
- WebUI 的 IP 状态下方同步显示最近数据上报、最近心跳上报和 API 连通状态；未联网时 IP 显示“未连接”。
- 串口用 `[REPORT]` 输出 HTTP 201、服务端 HTTP 错误或网络传输错误。WebUI 的 HTTP 2xx 成功回调最多保留最近 5 条且响应正文最多保留 64 字节；错误记录优先保留，最多使用 12 条总容量并保留最多 256 字节响应正文。

## 串口日志

使用 `pio device monitor -b 115200` 查看 ESP32 ROM/内核启动日志和系统初始化日志。`Serial.setDebugOutput(true)` 与 ESP-IDF `INFO` 日志级别已在启动阶段启用；EC11 和传感器不输出运行时调试日志。

## 构建和烧录

```bash
pio run
pio run -t upload
pio device monitor -b 115200
```

## 项目结构

```text
include/
  buzzer.h       # 低电平触发无源蜂鸣器接口与引脚
  control.h      # EC11 输入接口与引脚
  environment_status.h # 告警判断结果
  network_portal.h # 本地热点配网和 WebUI
  report_uploader.h # HTTP 定时上报与配置接口
  rtc_clock.h       # DS3231 I2C RTC、NTP 与手动校时
  sensors.h      # 环境传感器采集接口与引脚
  SSD1306.h      # OLED 绘制接口与引脚
  threshold_store.h # 阈值 NVS 存储
  thresholds.h   # 阈值数据模型
src/
  buzzer.cpp     # 非阻塞 2.4kHz 单次鸣叫控制
  control.cpp    # 编码器中断与按键消抖
  environment_status.cpp # 传感器超限判断
  network_portal.cpp # Wi-Fi 配网、DNS 引导、WebUI、凭据 NVS
  report_uploader.cpp # 上报 JSON、Bearer 鉴权和配置 NVS
  rtc_clock.cpp   # DS3231 I2C 读写、NTP 同步和上海时区转换
  sensors.cpp    # ADC 平均采样和 DHT11 检测
  SSD1306.cpp    # 监测与设置界面
  threshold_store.cpp # 阈值 NVS 校验与保存
  main.cpp       # 传感器与界面判断调度
```
